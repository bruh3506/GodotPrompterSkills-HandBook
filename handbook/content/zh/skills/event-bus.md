# 事件总线：跨系统广播变化

一句话：让互不认识的节点通过事件交流，避免彼此保存大量直接引用。

## 通俗解释

事件总线像广播站：玩家发出“捡到金币”事件，计分 UI、音效和任务系统各自收听，不需要玩家脚本挨个调用它们。

## 场景例子

关卡结束时，Level 节点发出 `level_completed`。结算 UI 打开，音乐切换，成就系统更新；以后加入录像系统也只需订阅这个事件。

## 专业要点

全局 EventBus 适合确实跨越场景树、发布者和订阅者无直接领域关系的事件。对象之间关系明确时，直接信号更容易追踪。避免用事件总线传输所有命令或产生隐式执行顺序；信号应有类型和清楚的所有权。

## 什么时候用

多个独立系统需要响应同一事件，且直接引用会造成不必要耦合时使用。先比较节点信号、依赖注入和 Autoload，不要为了“解耦”把调用路径藏起来。

## English learning

| English | 中文理解 | Example |
|---|---|---|
| publish an event | 发布事件；广播一件已发生的事 | The level publishes a completion event.（关卡广播完成事件。） |
| subscribe to an event | 订阅事件；收到通知后响应 | The score screen subscribes to the event.（计分界面订阅该事件。） |
